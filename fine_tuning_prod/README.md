# День 10: тюненая модель в проде (Mexamen, «Tú vs IA»)

LoRA-адаптер Дня 7 (`../fine_tuning_my_dataset`, Qwen2.5-1.5B-Instruct, вопросы теста Mexamen) слит с базой, переведён в GGUF, проквантован и подключён к приложению Mexamen как локальный сервис. В приложении есть экран **«Tú vs IA»**: пользователь и модель отвечают на одни и те же 5 вопросов, до ответа можно выбрать модель — «Ajustado» (тюн) или «Base».

**Главный вывод:** в Q4_K_M тюн занимает 940 МБ вместо 2950 МБ, не теряет качества от квантования (57.0% на 149 вопросах, как в Дне 7 до слияния) и отвечает **в 3.6 раза быстрее** базы с проработанным промптом (p50 2.6 с против 9.5 с на CPU). По точности подмена ничего не даёт и ничего не стоит: 57.0% против 59.7%, разница в пределах шума (p = 0.64). Выигрыш тюна — цена запроса, а не знания.

## Что где лежит

| Файл | Назначение |
|---|---|
| `merge_adapter.py` | слить адаптер с базой → `models/hf/mexamen-tuned-v1` (fp16) |
| `build_gguf.sh` | HF → GGUF f16 → Q8_0 и Q4_K_M, для тюна и для базы |
| `serve.py` | прокси на `127.0.0.1:8090`: алиасы `tuned`/`base`, ленивый запуск `llama-server`, промпт-профиль, CORS |
| `prompts.py` | профили промпта: `plain` (голый запрос, как учили тюн) и `fewshot` (правила + 3 примера для базы) |
| `registry.json` | модели, алиасы, история алиасов — единственный источник «что сейчас в проде» |
| `rollout.py` | `register` / `check` / `set` / `rollback` |
| `evalcheck.py`, `bench.py`, `compare.py` | прогон eval Дня 7 (149 вопросов вне обучения), замеры, парное сравнение |
| `results/` | `bench.json|md`, `compare.json` |
| `models/` (не в git) | `hf/` и `gguf/`, около 11 ГБ |

## Как получена модель

```bash
python3 -m venv .venv && .venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install transformers peft safetensors sentencepiece gguf numpy psutil huggingface_hub accelerate
git clone --depth 1 https://github.com/ggml-org/llama.cpp
cmake -S llama.cpp -B llama.cpp/build -DLLAMA_CURL=OFF && cmake --build llama.cpp/build -j6 --target llama-quantize llama-server llama-cli

.venv/bin/python merge_adapter.py     # 26 с на CPU, скачивает базу (3 ГБ)
./build_gguf.sh                       # f16 → Q8_0, Q4_K_M
```

Слияние в fp16 (как обучали). Проверка, что слияние верное: тюн в f16 даёт 85/149 = 57.0% — ровно цифра Дня 7 до слияния.

## Замеры (CPU, 8 ядер, 14 ГБ RAM, без GPU, `llama-server -t 6 -c 2048`, один процесс, `cache_prompt` выключен)

149 eval-вопросов Дня 7, greedy, `max_tokens = 128`. «Загрузка» — от запуска процесса до `/health`; RSS — память процесса после прогона.

| Вариант | Размер | Загрузка | RSS | Токенов/с | Латентность p50 / p95 | Токенов на входе | Accuracy | Строгий формат |
|---|---|---|---|---|---|---|---|---|
| тюн f16 | 2950 МБ | 5.3 с | 3.4 ГБ | 6.6 | 4.5 / 11.4 с | 93 | 57.0% | 100% |
| тюн Q8_0 | 1570 МБ | 2.2 с | 2.0 ГБ | 15.1 | 4.1 / 8.8 с | 93 | 57.7% | 100% |
| **тюн Q4_K_M (в проде)** | **940 МБ** | **1.8 с** | **2.0 ГБ** | **18.5** | **2.6 / 6.0 с** | **93** | **57.0%** | **100%** |
| база Q4_K_M + промпт (до подмены) | 940 МБ | 2.4 с | 1.7 ГБ | 16.1 | 9.7 / 13.2 с | 387 | 59.7% | 98% |
| база Q4_K_M, голый запрос | 940 МБ | 1.8 с | 2.5 ГБ | 18.5 | 8.7 / 10.5 с | 93 | 49.0% | 0% |

- **Квантование точность не съело:** 57.0 / 57.7 / 57.0% — разница в 1 вопрос. Q4_K_M в 3.1 раза меньше f16 и декодирует в 2.8 раза быстрее.
- **Почему тюн быстрее базы:** декодируют они одинаково (17–19 ток/с), но базе нужен промпт на 387 токенов вместо 93 (префилл на CPU) — отсюда 9.5 с против 2.6 с. Голая база без промпта не быстрее: она пишет по 114 токенов вместо 17 и формат не держит (0%).
- **Память:** около 1.7–2.0 ГБ на процесс. Две модели одновременно (тюн и база, как в сервисе) — около 4 ГБ.
- Время загрузки — с тёплым файловым кэшем; с холодного диска будет дольше. Первый запрос после простоя в приложении ждёт эту загрузку (таймаут клиента 90 с).

## Сравнение до и после подмены (`compare.py`, те же 149 вопросов, парный знаковый тест)

«До» — база + проработанный промпт: именно её и заменяет тюн. В Mexamen до этого не было живой LLM-модели (`LlmDistractorGenerator` не подключён в DI), поэтому сравнивается тюн с лучшей конфигурацией базы. Groq `llama-3.3-70b` не сравнивался: ключа в замерах нет, и это другая весовая категория.

| | База + промпт | Тюн (Q4_K_M) |
|---|---|---|
| Верно | 89/149 = 59.7% | 85/149 = 57.0% |
| Строгий формат | 98.0% | 100% |
| p50 / p95 | 9.5 / 13.1 с | 2.6 / 5.9 с |
| Токенов на входе | 387 | 93 |

Парное сравнение: только база права — 22, только тюн прав — 18, оба правы — 67, оба неправы — 42, **p = 0.64**. Качество неразличимо; на 149 вопросах различима разница порядка 10 п.п. Один прогон, greedy.

Что это значит для сервиса: подмена на тюн безопасна по качеству, формат ответа чуть надёжнее, запрос в 3.6 раза быстрее и в 4.2 раза короче. «Знаний о Мексике» тюн не добавил, и для приложения это не должно быть аргументом.

Сравнение на реальных запросах приложения: в экране «Tú vs IA» вопросы берутся из того же датасета, что и eval, а варианты ответа — те же дистракторы, что в квизе (в eval — «настоящие» неверные варианты из `questions.json`, в приложении при их нехватке — локальный fallback). Поэтому цифры выше — оценка, а не точное предсказание для приложения.

## Как подключено к приложению

Приложение ходит на `http://localhost:8090/v1/chat/completions` (OpenAI-совместимый). Поле `model` — алиас: `tuned` или `base`. Какая версия за алиасом, решает `registry.json`, а не приложение. Промпт-профиль привязан к модели в реестре: откат модели откатывает и её промпт.

```bash
.venv/bin/python serve.py          # 127.0.0.1:8090; llama-server поднимаются при первом обращении
curl localhost:8090/status         # алиасы, история, какие процессы запущены, время загрузки
```

- **Web (wasm).** Браузер вызывает `localhost` прямо со страницы (Vercel или локальная сборка). Прокси отвечает на preflight с `Access-Control-Allow-Origin` для разрешённых источников (`MEXAMEN_ALLOWED_ORIGINS`, по умолчанию Vercel-домен приложения и `http://localhost:8080|8081`) и `Access-Control-Allow-Private-Network: true` для Chrome. Чужой Origin заголовка CORS не получает. Работает только на этом компьютере; Safari запрещает https → http://localhost.
- **Android.** `adb reverse tcp:8090 tcp:8090`; для http на localhost добавлен `network_security_config.xml`.
- Если сервис не запущен, экран «Tú vs IA» показывает «IA: no disponible», а квиз и карточки работают как обычно.

## Переключение между тюном и базой без переката

1. **Для пользователя:** чипы «Ajustado» / «Base» на экране перед ответом; повторный запрос идёт к другому алиасу. Сервис перезапускать не нужно: оба бэкенда живут рядом.
2. **Для оператора:** смена версии за алиасом — правка `registry.json` через `rollout.py`. Прокси перечитывает файл по mtime, следующий запрос уже идёт к новой модели.

## Как выкатывать новую версию модели

Где лежит: GGUF — `models/gguf/<имя>-<квант>.gguf` (вне git, ~1 ГБ на версию), описание — запись в `registry.json` (`gguf`, `port`, `prompt`). Предыдущие версии остаются на диске и в реестре.

1. **Собрать:** `merge_adapter.py --name mexamen-tuned-v2` (с новым адаптером), `build_gguf.sh`; в реестр — `rollout.py register mexamen-tuned-v2-q4 --gguf models/gguf/mexamen-tuned-v2-Q4_K_M.gguf --prompt plain --port 8103`. Каждая версия — свой порт.
2. **Проверить перед выкаткой:** `rollout.py check mexamen-tuned-v2-q4` — поднимает отдельный `llama-server` и прогоняет 149 eval-вопросов. Проходит, если **строгий формат ≥ 95%**, **accuracy ≥ 50%**, **p95 ≤ 30 с**. Порог ловит поломку, а не улучшение: шум на 149 вопросах около ±8 п.п. (эталон: 57%).
3. **Выкатить:** `rollout.py set tuned mexamen-tuned-v2-q4` — сама прогоняет проверку, при провале выкатка отменяется и алиас не меняется; при успехе предыдущее значение уходит в `history`. Алиас меняется атомарно (запись во временный файл и `rename`).
4. **Откатить:** `rollout.py rollback tuned` — алиас возвращается на предыдущую версию; процесс предыдущей версии поднимется при первом запросе (около 2 с). Дополнительно к `history` старые версии лежат на диске, файлы удалять только после того, как новая версия отработала.

Проверено на этой машине: `bad-candidate` (база с профилем `plain`: формат 0%, accuracy 40%) — `set` отказал, алиас не изменился; `mexamen-tuned-v2-q8` (Q8_0 тюна, как заглушка «v2») — проверка пройдена, `set` переключил алиас, следующий запрос вернул `X-Model-Resolved: mexamen-tuned-v2-q8`; `rollback` вернул `mexamen-tuned-v1-q4`. Ничего перезапускать не пришлось.

## Ограничения

- Один прогон, один seed, greedy; замеры на CPU ноутбука. На другой машине цифры скорости будут другими, соотношения — похожими.
- Eval Дня 7 мал (149), доверительный интервал ±8 п.п.; разницу между версиями в 3–5 п.п. он не различит.
- Сервис однопоточный на модель (`-np 1`): параллельные запросы к одной модели встают в очередь.
- Нет авторизации: прокси слушает только `127.0.0.1`. Для доступа с других машин нужен туннель или VPS с ключом (не сделано).
- Проверка перед выкаткой не ловит деградацию вне домена (День 8: тюн «протекает» форматом `Respuesta:` на посторонних запросах); её здесь нет.
- В браузере и на Android-устройстве интеграцию я не прогонял: устройства по USB не было, браузер не открывал. Проверены: прокси `curl`-ом (запросы, preflight, чужой Origin), код приложения — unit-тестами и компиляцией для Android и wasm.
